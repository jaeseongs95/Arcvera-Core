# R35 기능과 동작 경계

R35는 공식 Codex 0.166.0 기반 패치입니다. R34 실행 파일·태그·기존 설치는 동결한 채 별도 후보를 준비합니다.

## 메모리와 세션

대화 입력의 `/memory enable on` 또는 명시적인 자연어 활성화 요청은 memories 기능과 읽기·생성 설정을 함께 변경합니다. 비활성 상태의 기억 요청이 설정을 몰래 켜지는 않습니다. 저장 접수, thread에서 읽기 가능함, 모델이 만든 요약의 통합은 각각 다른 단계입니다. 프로젝트 범위와 기존 세션의 명시적 off를 보존합니다.

세션별 context window는 모델 한도를 올릴 수 없습니다. 저장된 service tier는 재개 시 전역 기본값으로 덮지 않습니다. 자연어 압축 요청은 요청이 나온 모델 턴의 정상 완료를 기다린 뒤 기존 idle admission을 한 번 시도합니다. 중단·실패·세션 교체 또는 busy 결과를 자동 재요청하지 않습니다.

## 로깅과 캐시 진단

자연어로 로깅 상태 조회·켜기/끄기, 캐시 관측 상태·response/wire 설정을 요청할 수 있도록 session control을 연결합니다. 일반 로그와 전용 캐시 관측은 별도 스위치이며 wire 관측은 response 없이 켤 수 없습니다.

설정 저장은 다음 프로세스 시작부터 적용됩니다. 현재 시작 때 선택된 모드, 저장 파일, 다음 실행 예상 모드와 재시작 필요 여부를 따로 반환합니다. 수집 worker 생존·이벤트 생성·Drive 업로드 완료를 이 상태만으로 추정하지 않습니다. 완성된 배치 파일을 다시 append하지 않는 기존 저장 방식을 유지합니다.

SSE에서 이미 받은 완료 usage가 알림 backpressure나 닫힌 수신자 때문에 관측되지 않던 경로를 수정합니다. 캐시 적중률이나 정책·key·TTL 자체를 바꾼 패치가 아닙니다. 관측이 꺼져 있던 구간을 적중률 0으로 해석하지 않습니다.

## 예약·정리·언어

예약 프롬프트는 약 50 grapheme으로 접어 표시하고 펼쳐 확인할 수 있게 합니다. 저장한 prompt와 모델에 제출할 원문을 줄이지 않습니다. 자연어 예약 추가·목록·중지·재개·삭제는 CLI cron 도구를 사용합니다. CLI 종료 시 사라지는 예약을 자동 복원했다고 표시하지 않습니다.

하위 에이전트 정리는 preview의 정확한 대상과 현재 상태를 확인한 뒤 명시적인 확인으로 수행합니다. 부모·현재 세션·진행 중 작업 보호와 부분 실패 구분을 유지합니다. 정리 확인 문구와 토큰은 선택 언어를 따릅니다.

언어는 `/language ko` 또는 `/language en`으로 전역 저장하고 다음 실행부터 적용합니다. 프로젝트마다 별도 UI 언어 파일을 만들지 않습니다. 사용자 문장·프로젝트 이름·경로·명령·서버 응답의 내용은 번역하지 않습니다. 고정 이미지 붙여넣기와 제출 remap의 충돌은 같은 키 판정으로 거절합니다.

## App Server와 Cloud

`codex app-server daemon start --first-installation`은 도움말에서 실제 지원을 확인한 경우에 사용합니다. lifecycle lock을 잡은 뒤 기존 설치·설정·복구 흔적 12경로를 확인하며, 이미 있는 상태를 덮거나 초기화하지 않습니다. `--existing-installation`과 함께 사용할 수 없습니다.

CLI와 공유 daemon의 전체 버전 문자열 차이만으로 연결을 거절하지 않습니다. initialize, private socket·peer 검증, 명시적 기능 override와 실제 RPC 실패 처리는 별도 경계로 유지합니다. 연결 성공은 동일 패치 서버 사용 또는 모든 기능의 호환성을 뜻하지 않습니다. 기본 socket을 명시한 `--remote`도 LocalDaemon으로 분류되는 기존 정책은 유지됩니다. 공유 daemon을 자동 재시작하지 않습니다.

선택 capability 선언, 실제 빈 thread attach, 이벤트 수신, 모델 turn 완료는 별도로 확인합니다. Cloud 목록의 부분 조회 오류를 빈 정상 결과처럼 숨기지 않습니다. 실제 서비스 계정·모바일 연결 성공은 단위 시험만으로 보장하지 않습니다.

최종 검증 결과·실행 파일 SHA·Desktop 조합은 릴리스 노트의 실제 기록을 따릅니다.
