# R36 설계와 개발 범위

R36은 R35 후보 `2e9f6050aac19bb230dfcff10138d255edc613f7`에서 분리한 개발판이다. 이 문서의 수용 기준은 구현·시험 완료를 뜻하지 않는다. R34 설치·릴리스와 기존 R35 작업 사본, 사용자 데이터, 공유 daemon은 변경하지 않는다.

## 공식 버전 기준

2026-11-03 GitHub Releases API 조회에서 최신 안정판은 `rust-v0.166.0`(2026-10-29), 최신 시험판은 `rust-v0.167.0-alpha.4`(2026-11-03)였다. 현재 기반은 이미 0.166.0이므로 안정판을 업그레이드했다고 표시하지 않는다. 최종 제품 빌드 전에 다시 조회하고 새 안정 릴리스가 있으면 그 소스로 갱신한다. 시험판을 안정판으로 간주하지 않는다. 공식에서 해결한 결함은 중복 구현하지 않고, openDIY 패치의 필요성과 회귀 여부를 대조한다.

## 하위 에이전트 표시

현재 대화 루트의 실제 하위 작업만 이벤트로 갱신한다. 기본 표시는 입력창 아래 한 줄의 상태별 개수다. 펼치면 최대 3개 행과 내부 스크롤을 사용하며, 터미널이 작으면 행 수를 더 줄인다. 15개나 100개를 생성해도 목록 전체가 대화 영역을 밀어내지 않는다.

사용자 확인이 필요한 작업, 실패, 실행 중 순서로 우선 표시한다. 같은 우선순위에서는 순서를 안정적으로 유지해 갱신마다 항목이 뛰지 않게 한다. 각 행은 이름·현재 작업·경과 시간을 표시하되 실제 제공되지 않는 시간이나 토큰 수를 추정하지 않는다. 완료 항목은 짧게 표시한 뒤 상세 목록에서 확인하며, 표시에서 숨기는 것과 영구 삭제를 분리한다. root 전환 시 다른 대화의 작업이 섞이지 않아야 한다.

## 과거 종료 에이전트 정리

현재 정리 구현은 저장된 자손도 나열하지만, 현재 프로세스에서 로드되지 않은 세션에는 삭제 snapshot을 만들지 않는다. 여러 제외 사유가 `preserved`로 합쳐지는 것도 개선 대상이다.

저장소의 기존 소유·writer·lifecycle 잠금과 queue/goal 보호를 재사용한다. 미리보기와 실행 사이의 상태 변화, 다른 프로세스의 사용, 부모·현재 대화, 미완료·불명 상태는 삭제를 막아야 한다. 과거 종료 세션은 모델을 실행하거나 대화를 복원하지 않고 metadata로 확인한다. 각 제외 사유를 반환하며, 안전한 판정이 불가능한 항목은 사유와 함께 보존한다. 시험은 격리 fixture만 사용하며 실제 사용자 세션 삭제는 이번 개발의 검증 수단으로 삼지 않는다.

## Cloud와 GitHub CI

R35에는 Cloud 목록의 부분 조회 오류 표시가 포함돼 있으나, 도움말과 단위 시험만으로 실제 계정의 호출 성공이 확인된 것은 아니다. 기존 Cloud 명령과 공식 경로를 재사용하고 실패·권한 부족·환경 없음·지원 안 됨을 구분한다. 실제 원격 작업 제출이 필요한 검증은 별도 실행 근거를 남긴다.

GitHub CI 관측은 기존 `gh`를 이용한 읽기 전용 조회로 구현한다. 저장소·commit SHA·branch·run·상태·결론·URL을 구분하고, 관측한 commit이 현재 HEAD와 일치하는지 확인한다. 명시적으로 요청한 watch만 제한된 주기로 조회하며 종료·취소·시간 제한을 지킨다. CI 재실행, workflow 등록, 댓글 게시나 자격증명 수집은 수행하지 않는다. 조회 실패와 아직 실행 없음은 서로 다른 결과다.

## Fast 범위와 압축 지연

Fast(`priority`)와 `ultrafast`의 catalog·정책 지원을 구분한다. 부모의 설정 변경이 기존·새 하위 작업, 다음 모델 요청, 압축 요청, 재개에 적용되는 경계를 기존 공식 구현과 격리 회귀시험으로 확인한다. 이미 전송한 요청에 설정 변경이 소급된다고 설명하지 않는다.

압축 지연은 준비·선행 작업 대기·서버 요청/재시도·결과 반영·history flush·완료 알림 구간을 나눠 조사한다. 실측이 없는 병목을 단정하지 않는다. 기존 tracing을 우선 사용하고 추가 계측에는 phase·경과 시간·시도·결과만 넣는다. 대화 원문·프롬프트·인증값은 계측하지 않는다. 확인된 결함만 최소 수정한다.

## 검증과 개발 분리

소스와 시험은 별도 R36 브랜치에서 개발한다. 기존 warm cache와 자원 보호를 재사용하며 빌드 프로세스를 여러 개 동시에 시작하지 않는다. 실제 시험 결과·종료 코드·후보 SHA를 연결하고, 미실행과 통과를 구분한다. 최종 변경의 수용 근거 확인과 새로운 독립감사를 거친다. 이번 요청만으로 main 병합·릴리스·설치를 실행하지 않는다.
