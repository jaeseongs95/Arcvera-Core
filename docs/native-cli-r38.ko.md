# R38 시작 경고 수정 후보

R37 공개 실행 파일은 동결 상태다. 이 문서는 R37 이후 별도 개발 후보의 범위를 설명하며 R38 최종 빌드·공개·설치 완료를 뜻하지 않는다.

## 공식 0.167 기반 전환

R38은 공식 `rust-v0.167.0`의 commit `086ccc833bc9cf01024ad2dd6af7dbd421b6bf9a`를 기반으로 이식 중이다. 버전은 `0.167.0+native-r38.20261106`으로 구분한다. 공식의 기본 keymap 캐시, 새 세션 및 backend 전환의 초안 보존, human approval, 자동 압축의 usage 경계, MCP 세션별 override와 연결 수명 변경을 함께 대조한다.

로컬의 플러그인 `.git` 제외, 암시적 daemon의 전체 빌드 버전 검사, Stop 안내 및 메인 에이전트 마우스 복귀는 공식 기능과 구별해 유지한다. 아래 0.166 기반 개발 후보의 시험 결과는 이력이며, 새 0.167 후보의 통과 근거로 사용하지 않는다. 새 후보는 별도 시험과 Desktop 공동검증·독립감사 후에 최종 빌드한다.

## 플러그인 캐시

동일 버전을 다시 준비할 때 저장소 `.git/index`와 같은 메타데이터까지 비교하면 실제 플러그인 내용이 같아도 설치 디렉터리를 교체하려 할 수 있다. Windows에서는 사용 중인 자식 디렉터리의 cwd 또는 열린 파일 때문에 상위 rename이 거절될 수 있다.

새 staging 복사와 설치 내용 비교에서 이름이 정확히 `.git`인 항목만 제외한다. 기존 사용 중인 캐시의 `.git`를 별도로 삭제하지 않는다. 실제 payload의 변경·추가·삭제, 권한 및 읽기 실패는 기존 교체·오류 경로를 유지한다. 특정 운영 오류의 정확한 잠금 보유자를 식별했다는 주장은 하지 않는다.

## 자동 공유 서버 연결

기존 소켓에 대한 암시적 연결, 자동 시작 결과 이후 실제 handshake, 재연결에서 CLI의 전체 빌드 버전을 대조한다. 다르거나 확인되지 않으면 해당 클라이언트 연결을 닫는다. 초기 시작은 현재 CLI의 embedded backend를 사용하며 그 이유를 화면에 표시한다. 진행 중 대화의 재연결에서는 다른 backend로 옮기지 않고 거부 이유를 표시하며 대화 ID·draft·대기 입력을 보존한다. 명시적 원격 endpoint와 사용자가 선택한 공유 연결의 정책은 유지한다.

연결 거절은 공유 서버 종료·업데이트 요청이 아니다. 현재 CLI 실행 경로·서버가 보고한 버전·접속 소켓을 구분하고 한국어/영어 catalog로 안내한다. 소켓만 보고 실행 중인 서버의 실행 파일 경로를 안다고 표시하지 않는다.

## Stop 설정 교정 도구

`Stop` 이벤트는 `additionalContext`를 출력할 수 없어 `additionalContextLimit`가 무시된다. Stop hook 자체가 비활성화됐다는 뜻은 아니다.

`scripts/install/normalize_stop_hook_config.py <명시한 hooks.json 경로>`는 기본값으로 미리보기만 수행한다. 명시한 `--apply`에서만 Stop handler의 해당 속성을 제거하며 원본 백업, 동시 변경 거절, 비대상 원문·인코딩·줄바꿈 보존을 적용한다. 다른 이벤트나 hook 명령을 바꾸거나 hook을 실행하지 않는다. Python이 필요하며 아직 배포 설치기와 연결하지 않은 개발용 도구다. 사용자 운영 hooks 설정은 이 개발 단계에서 적용하지 않았다. 초기 읽기 경쟁과 비정상 종료 시 백업 복구의 한계는 시험 문서를 따른다.

## 플러그인 다시 읽기의 Stop 경고

`/reload_plugin`은 사용자 설정과 hook을 다시 검증하므로, 같은 파일에 지원하지 않는 Stop 속성이 남아 있으면 같은 경고를 다시 반환한다. 설정 재로드와 다음 capture의 MCP 재연결 요청이 처리됐다는 응답이며 MCP 서버 준비 완료를 의미하지 않는다.

R38은 재로드 결과·일부 설정 경고·실패·잘못된 응답·오래된 화면 요청을 한국어/영어 catalog로 안내한다. 서버가 반환한 경고와 파일 경로는 보존한다. 지원하지 않는 속성의 진단에는 해당 handler의 `additionalContextLimit`만 제거하고 Stop hook 및 command는 유지하라는 설명을 추가한다. 재로드가 사용자 설정을 자동으로 삭제하거나 경고를 숨기지는 않는다. 위 교정 도구로 명시적으로 해당 속성을 제거한 뒤 다시 읽으면 이 경고가 사라지는지를 격리된 실제 서버 fixture로 검사한다.

## 메인 에이전트로 마우스 복귀

하단 에이전트 목록에 `메인` 행을 함께 표시한다. 같은 마우스 선택 경로로 자식 대화와 메인을 오가며, 메인은 하위 에이전트 실행·대기 개수나 정리 대상에 합산하지 않는다. 접힌 목록·좁은 화면·마지막 자식 숨김에서도 메인 복귀 경로를 유지한다. 전체 상세행 높이 제한은 유지하며 메인과 자식의 현재 위치는 별도 표시한다.

호버는 작은 표시자의 밑줄만 바꾼다. 행 전체 반전과 호버에 따른 문구 교체를 제거해 글자와 레이아웃을 안정적으로 유지한다. 초안·진행 중 turn·대기 입력 보존과 잘못된 root의 클릭 거부는 기존 탐색 경로의 시험으로 확인한다. [마우스 복귀와 호버 사례](r38-agent-main-return-test-cases.ko.md)는 실제 사용자 GUI의 체감 검증을 대신하지 않는다.

## Windows 0.166 기반 개발 후보의 실행 결과 이력

격리된 같은 시험 사본과 기존 cache에서 `--offline --locked --profile dev-small --target x86_64-pc-windows-msvc -j2`로 실행했다. plugin store 38개, hook discovery 2개와 중복을 제외한 TUI 125개가 통과했다. Stop 교정 도구는 17개 중 16개 통과·실제 symlink 권한 부족 1개 SKIP이다. TUI 11필터의 종료 코드는 모두 0이며 Rust/FTL bytes를 시험 receipt와 직접 대조했다.

원본 cache 동작 비교의 6개 실제 실패, 초기 통합 fixture 오류, 별도 test compile 오류, 명시적으로 취소한 이전 실행은 원시 자료를 로컬에 보존했다. 새로운 실제 통과로 원래 결과를 덮어쓰지 않는다. 자연어 reload 별도 RPC·invalid ACK 실서버·운영 UI 체감·다른 OS·장시간 부하는 미검증이다. 이 결과는 최종 R38 실행 파일이나 Desktop 공동 설치 시험을 대신하지 않는다.
