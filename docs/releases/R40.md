# OpenDIY Codex R40 — Reconnection, context, and usability improvements / 재연결·컨텍스트·사용성 개선

## English

### Overview

R40 improves temporary MCP reconnection and context lookup responsiveness, and fixes hook boundaries, scrolling, Korean text, and confirmed memory/provenance defects.

| Item | Value |
| --- | --- |
| Version | `0.167.0+native-r40.20261108` |
| Platform | Windows x86-64 |
| Upstream base | Codex 0.167.0 |
| Release status | Stable release; complete ZIP and individual executable assets |

### Changes

- Temporary MCP reconnection in the TUI distinguishes owners and execution generations and improves cancellation and existing-endpoint preservation. Requests with an unknown outcome are not automatically resent.
- Context lookup does not block other processing; hook output and execution boundaries are corrected.
- Mouse scroll sensitivity, Korean text, and the main marker in expanded child-task lists are improved.
- Confirmed memory/provenance defects are corrected. A full memory redesign, new CodeMode architecture, broad refactoring, and structural caching improvements are excluded.

### Getting started

1. Download `opendiy-codex-r40-windows-x86_64.zip` and `SHA256SUMS.txt` from this release.
2. Compare the ZIP's SHA-256 with the checksum file and the table below, then extract it into a new folder with its directory layout intact.
3. Run `bin\codex.exe` from the package. A CMD launcher is optional.

Keep `codex-package.json`, `package-receipt.json`, and the `bin` folder together. Retain the previous package for recovery.

| Entry point | Purpose |
| --- | --- |
| `bin\codex.exe` or `codex-patched.cmd` | Default startup; may reuse a compatible local shared server, depending on installation and settings. |
| `codex-local.cmd` | Uses `--no-daemon` to start an embedded backend separate from the existing shared server. |
| `bin\codex.exe --remote <address>` | Connects to an explicit remote server with the required authentication configured. |

The included `codex-patched.cmd` forwards arguments to the CLI. It does not replace an existing server version, configure a remote address, or pair a mobile device. If the implicitly selected server is incompatible or its version cannot be verified, startup may use the embedded backend. Check the actual server identity.

When using individual executables, use `codex.exe`, `codex-app-server.exe`, and `codex-code-mode-host.exe` from the same R40 release. Keep the helper beside the executable being run, under its original filename. A missing helper can cause `os error 2`. These three files do not make a complete managed-server installation package. Voice resources, launchers, updater support, and the server update below require the complete ZIP.

The ZIP's `USAGE.ko.md` remains frozen with the package. Consult this note as well for default startup and shared-server updates.

### Shared server update

**Finish active work and run this in a separate PowerShell window, outside the Codex conversation's shell tools.** Replacing the server disconnects clients and may interrupt active or queued work. Changing a CLI path or Desktop setting alone does not replace a running shared server.

From the root of the extracted complete package, run the following and answer the package-copy confirmation:

```powershell
& ".\bin\codex.exe" app-server daemon update --from-cli
if ($LASTEXITCODE -ne 0) { throw "Shared server update failed; review the error above." }
& ".\bin\codex.exe" app-server daemon start --existing-installation
if ($LASTEXITCODE -ne 0) { throw "Shared server startup failed; review the error above." }
& ".\bin\codex.exe" app-server daemon status --json
```

`--from-cli` copies the complete package being run and pins it as the managed server version. It requests normal shutdown, waits for the configured grace period, and may force termination if the old server remains. It does not delete existing authentication or conversation storage.

Before reconnecting the CLI or Desktop, check that the final JSON reports `status` as `running` and that `managedCodexVersion`, `appServerVersion`, and `cliVersion` all equal `0.167.0+native-r40.20261108`. Connection success and matching versions do not replace full compatibility testing.

If you see `this CLI has no complete local package`, check the executable path and package layout. Extract the complete ZIP into a new folder and use its `bin\codex.exe`. Do not substitute a `codex-app-server.exe` path for the `app-server` subcommand. If the result is unclear or the update fails, inspect the status and error before repeating the update.

### Known limitations

The **original policy-test failure (RED) is retained**. Its fixture depended on a debug-only management-path hook disabled in release builds and did not supply the policy. Observations of collision, invalid-name, and disabled-state rejection and existing-endpoint preservation are separate. Final-release OS-managed policy loading and identity-match acceptance/mismatch rejection remain **not run (NOT_RUN)**. The original failure is not represented as an all-pass RPC result.

Existing constrained settings and permission checks are preserved. Relevant source-identity checks, four historical native regressions, and policy RPC records do not demonstrate the final OS policy-supply path.

Direct OS keyboard input, first-time installation, physical voice behavior, sustained workloads, and resolution of all GUI delays and memory growth are unverified. Synthetic tests do not establish real-model compaction quality. Four omitted build observations and one image-query error are not treated as normal zero values.

Existing user data, authentication, and ongoing work are preserved. Installation, shared-server selection, desktop shortcuts, update schedules, collection targets, and mobile connections are not switched automatically. Build-setting differences do not establish equivalent performance or reduced memory use.

### 개요

임시 MCP 재연결과 컨텍스트 조회의 응답성을 보완하고, 후크 경계·스크롤·한국어 표시와 확인된 메모리·상속 출처 결함을 수정합니다.

| 항목 | 값 |
| --- | --- |
| 실행본 | `0.167.0+native-r40.20261108` |
| 운영체제 | Windows x86-64 |
| 공식 기반 | Codex 0.167.0 |
| 공개 상태 | 정식 릴리스 · 전체 ZIP과 개별 실행 자산 제공 |

### 변경 사항

- TUI 임시 MCP 재연결에서 소유자와 실행 세대를 구분하고, 취소와 기존 endpoint 보존 경계를 보완합니다. 결과가 불명확한 사용자 요청은 자동 재전송하지 않습니다.
- 컨텍스트 조회가 다른 처리를 막지 않도록 하고, 후크 출력·실행 경계를 수정합니다.
- 마우스 스크롤 감도, 한국어 문구, 펼친 하위 작업 목록의 main 표시를 개선합니다.
- 확인된 메모리·상속 출처 결함을 수정합니다. 메모리 전면 개편·새 CodeMode 구조·전체 리팩토링·구조적 캐싱 개선은 포함하지 않습니다.

### 시작하기

1. 이 페이지의 `opendiy-codex-r40-windows-x86_64.zip`과 `SHA256SUMS.txt`를 받습니다.
2. ZIP의 SHA-256을 아래 표와 체크섬 파일에 대조하고 새 폴더에 폴더 구조를 유지해 압축을 풉니다.
3. 패키지 루트의 `bin\codex.exe`를 실행합니다. CMD 사용은 필수가 아닙니다.

`codex-package.json`, `package-receipt.json`, `bin` 폴더를 함께 유지합니다. 이전 패키지는 복구용으로 보관합니다.

| 실행 경로 | 용도 |
| --- | --- |
| `bin\codex.exe` 또는 `codex-patched.cmd` | 기본 실행. 설치 상태·설정에 따라 호환되는 로컬 공유 서버를 재사용할 수 있습니다. |
| `codex-local.cmd` | `--no-daemon`으로 기존 공유 서버와 분리된 내장 백엔드를 실행합니다. |
| `bin\codex.exe --remote <주소>` | 필요한 인증을 설정한 원격 서버에 명시적으로 연결합니다. |

ZIP에 포함된 `codex-patched.cmd`는 인자를 CLI에 그대로 전달합니다. 기존 서버 교체·원격 주소 설정·모바일 페어링은 수행하지 않습니다. 자동 선택 서버가 호환되지 않거나 버전을 확인할 수 없으면 내장 백엔드로 실행될 수 있으므로 실제 서버 식별 정보를 확인합니다.

개별 EXE를 쓸 때는 같은 R40의 `codex.exe`, `codex-app-server.exe`, `codex-code-mode-host.exe`를 사용합니다. helper는 실제 실행 EXE와 같은 폴더에 원래 이름으로 둡니다. 누락되면 `os error 2`가 발생할 수 있습니다. 세 EXE만으로는 관리형 서버 설치용 전체 패키지가 되지 않습니다. 음성·launcher·updater와 아래 서버 업데이트에는 전체 ZIP이 필요합니다.

ZIP 안의 `USAGE.ko.md`는 당시 패키지와 함께 동결된 안내입니다. 기본 실행·공유 서버 업데이트는 이 노트도 함께 확인하십시오.

### 공유 서버 업데이트

**진행 중 작업을 마친 뒤, Codex 대화 안의 셸 도구가 아닌 별도 PowerShell에서 실행합니다.** 서버 교체로 연결이 끊기고 진행 중이거나 대기 중인 작업이 중단될 수 있습니다. CLI 파일이나 Desktop 설정만 바꿔도 실행 중인 공유 서버가 교체되지는 않습니다.

전체 ZIP을 푼 루트 폴더로 이동한 뒤 실행하고, 패키지 복사 확인 질문에 답합니다.

```powershell
& ".\bin\codex.exe" app-server daemon update --from-cli
if ($LASTEXITCODE -ne 0) { throw "Shared server update failed; review the error above." }
& ".\bin\codex.exe" app-server daemon start --existing-installation
if ($LASTEXITCODE -ne 0) { throw "Shared server startup failed; review the error above." }
& ".\bin\codex.exe" app-server daemon status --json
```

`--from-cli`는 실행한 전체 패키지를 복사해 공유 서버 버전으로 고정합니다. 기존 서버에 정상 종료를 요청하고 설정된 유예 시간까지 기다린 뒤, 남아 있으면 강제 종료할 수 있습니다. 기존 인증정보와 대화 저장소는 삭제하지 않습니다.

마지막 JSON의 `status`가 `running`이고 `managedCodexVersion`, `appServerVersion`, `cliVersion`이 모두 `0.167.0+native-r40.20261108`인지 확인한 뒤 CLI나 Desktop을 다시 연결합니다. 연결 성공과 버전 일치는 전체 기능의 호환성 시험을 대신하지 않습니다.

`this CLI has no complete local package` 오류가 나오면 실행 경로와 패키지 구성을 확인합니다. 전체 ZIP을 새 폴더에 풀고 그 루트의 `bin\codex.exe`를 사용하십시오. `codex-app-server.exe` 경로를 `app-server` 서브커맨드 자리에 넣지 마십시오. 결과가 불명확하거나 실패하면 상태와 오류부터 확인하고 업데이트를 반복 실행하지 마십시오.

### 알려진 제한

관리 정책 시험의 **원 실패(RED)는 유지**합니다. release에서 비활성화되는 debug 전용 관리경로 훅을 전제로 한 fixture가 정책을 공급하지 못했습니다. 기존 충돌·잘못된 이름·disabled 거절 및 기존 endpoint 유지 관측과 별개로, 최종 release의 OS 관리정책 로드와 identity 일치 허용·불일치 거절은 **미실행(NOT_RUN)**입니다. 원 실패를 전체 RPC 통과로 표시하지 않습니다.

기존 constrained 설정·권한 검사는 보존했습니다. 관련 소스 동일성과 당시 native 회귀 4개·정책 RPC 기록은 최종 OS 정책 공급 경로의 실증이 아닙니다.

직접 OS 키보드 입력, 최초 설치, 물리 음성, 장시간 운영 부하와 모든 GUI 지연·메모리 증가 해결은 미검증입니다. 실제 모델의 압축 의미 품질도 위 합성 시험으로 보장하지 않습니다. 빌드 관측의 누락 4건과 이미지 조회 오류 1건을 정상 0으로 해석하지 않습니다.

기존 사용자 데이터·인증·진행 중 작업을 보존합니다. 기존 설치·공유 서버·바탕화면 경로·업데이트 예약·수집 대상·모바일 연결을 자동 전환하지 않습니다. 빌드 설정 차이만으로 이전 후보와 실행 성능이 같거나 메모리가 개선됐다고 주장하지 않습니다.
