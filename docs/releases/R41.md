Arcvera-Core uses independent Semantic Versioning; upstream Codex 0.167.0 identifies source provenance. Arcvera-Core's own public CLI commands/options, app-server protocol and native-tool APIs define its versioned interface. Official Codex CLI compatibility or interchangeability is outside support scope; OpenAI server communication and the required server API/authentication paths remain supported. From 1.0.0, incompatible public-interface changes increment the major version, compatible features the minor version, and compatible fixes the patch version. The initialization contract requires the exact full Core release version, including prerelease and build metadata; clients must verify each target release. R41/R42 track work scope and are not release versions. This feature release is intended as `1.0.0`, with tag `v1.0.0`.

### Changes

- Initialization now requires `capabilities.extensions["arcvera/core"].version` to equal the server's complete Core version. Missing, malformed and unequal declarations are rejected with JSON-RPC error `-32600` before session initialization. Bundled first-party clients declare their built Core version; Desktop keeps its own UI version in `clientInfo.version`.
- Seven unused workspace packages were removed: `codex-agent-extension`, `codex-guardian-v3`, `codex-cloud-client`, `codex-core-api`, `codex-thread-manager-sample`, `codex-v8-poc`, and `codex-utils-readiness`. Required Windows/sandbox, voice and configuration helpers remain. Declared dependency-closure and lockfile checks do not substitute for executable tests.
- OpenDIY-specific batch logging, cache response/wire diagnostic recording, Drive export and their session controls have been removed. Official Codex logging, telemetry and conversation storage remain. Legacy logging settings are ignored; existing settings and log files are not deleted or migrated automatically. Earlier release notes describe historical behavior.

- A host-owned, vendor-independent index records source IDs, task states, dependencies, and exclusion/reactivation events without storing conversation bodies in the index.
- Original digests and host-prepared view digests remain distinct across Core checkpoint restore and local-store migration. A truncated view cannot establish a new raw original's identity; anonymous repeats are reconciled by occurrence count, and omitted resident sources stay conservative. Actual rollback clears abandoned task policy instead of restoring a compaction checkpoint's policy.
- Inter-agent message recording waits for confirmed delivery before taking the persistence permit. Uncertain response-item appends mark recovery failure before releasing that permit so later policy changes cannot accept an unpersisted source.
- `set_focus` selects the current task; its dependency closure retains referenced completed work and excludes unrelated tasks' classified details even when active. Without focus, active-task roots remain conservative. User/control/unknown/unclassified/legacy opaque sources and incomplete tool groups remain protected; new host-scoped summaries follow their captured focus.
- The native `context_index` tool provides related metadata `list` (explicit `include_unrelated` for archive navigation), bounded original `read`, atomic revision-checked `apply`, and bounded `audit` summaries or exact-event JSON chunks. Metadata and historical content do not grant authority. External-memory retrieval remains disabled where disabled.
- Sampling, prewarm and local/remote compaction use the projection integration. Policy-revision changes invalidate WebSocket continuation; stale foreground/background compaction must not replace a newer policy. Current user/control/unclassified roots survive independently of summaries. An uncertain durable mutation blocks further sampling/mutation/compaction pending cold resume. Pre-relocation source regression covered these failure boundaries in the selected local suites; final executable verification remains pending. The [design and migration/recovery guide](../context-index.md) specifies the boundaries and verification obligations.
- Only a successful native apply's completed call/result group leaves model replay; raw history and audit remain preserved. Request navigation contains reachable task labels and bounded identifiers, without automatic cache timestamps.
- Latest completed sampling usage reports response-level cache `hit`/`miss`/`unknown`/`invalid`, host observation time and captured request-index revision. Aggregate counters do not identify per-source hits. Upstream retention/expiry metadata is not provided: TTL and expiry stay `unknown`, and no adapter-confirmed expiry support is claimed. Cache state never deletes originals or required context.
- Remote-compaction trace request metadata borrows input fields instead of eagerly cloning them into a JSON value before checking whether tracing is enabled. Runtime latency and memory effects remain unmeasured.
- The previously assigned broader R41 architecture work moves to the [R42 roadmap](../roadmap/R42.md).

### Getting started

Previous clients, including the official Codex CLI, cannot initialize this server without the new declaration. Use the CLI/server/helper from the same complete release and a Desktop release verified with Core 1.0.0. Custom clients must read the intended server version from a verified package or daemon status and send `"capabilities":{"extensions":{"arcvera/core":{"version":"1.0.0"}}}` in `initialize`; do not put the Desktop UI version there. After a rejected declaration, a corrected initialization may be sent on the same connection. Do not bypass an error by guessing versions or changing authentication. Keep existing configuration, authentication and conversation files; this connection change does not require deleting them. Before an authorized server/data upgrade, retain the previous complete package and an appropriate backup. Restoring an old executable alone is not a supported downgrade of data written by 1.0.0.

The following instructions apply after the complete verified R41 package is published. This candidate has no verified downloadable R41 assets yet.

1. Download `arcvera-core-1.0.0-windows-x86_64.zip` and `SHA256SUMS.txt` from the eventual release.
2. Compare the ZIP's SHA-256 with the final checksum file and table, then extract it into a new folder with its directory layout intact.
3. Run `bin\codex.exe`. A CMD launcher is optional. Keep `codex-package.json`, `package-receipt.json`, and the `bin` folder together; retain the complete previous package for recovery.

| Entry point | Purpose |
| --- | --- |
| `bin\codex.exe` or `codex-patched.cmd` | Default startup; may reuse a compatible local shared server, depending on installation and settings |
| `codex-local.cmd` | Uses `--no-daemon` for a separate embedded backend |
| `bin\codex.exe --remote <address>` | Explicit remote connection with the required authentication |

The included default launcher forwards arguments; it does not replace an existing server, configure a remote address, or pair a mobile device. An incompatible or unverified implicit server can cause startup to use the embedded backend. Check the actual server identity.

Individual `codex.exe`, `codex-app-server.exe`, and `codex-code-mode-host.exe` must come from the same release. Keep the helper beside the executable being run under the exact filename `codex-code-mode-host.exe`; a missing helper can cause `os error 2`. These three files are not a complete installation package. Voice resources, launchers, updater support, and the managed-server update require the complete ZIP.

### Shared server update

This procedure is documentation for a future verified package; it has not been executed for this candidate. Publication does not install R41 or switch an operational server. Before an authorized switch, finish active work and use a separate PowerShell window outside the conversation's shell tools. Updating disconnects clients and can interrupt active or queued work. A CLI path or Desktop setting alone does not replace a running server.

From the extracted complete package root, after reviewing the [migration and recovery limits](../context-index.md#persistence-migration-and-recovery), run:

```powershell
& ".\bin\codex.exe" app-server daemon update --from-cli
if ($LASTEXITCODE -ne 0) { throw "Shared server update failed; review the error above." }
& ".\bin\codex.exe" app-server daemon start --existing-installation
if ($LASTEXITCODE -ne 0) { throw "Shared server startup failed; review the error above." }
& ".\bin\codex.exe" app-server daemon status --json
```

`--from-cli` copies the complete package and pins it as the managed server version. It requests shutdown and may force termination after the grace period. It does not delete authentication or conversation storage. Answer its package-copy confirmation only when ready for the interruption.

Before reconnecting, require `status` to be `running` and `managedCodexVersion`, `appServerVersion`, and `cliVersion` to match the final published version. The intended value is `1.0.0`; it remains pending final executable verification. Matching versions alone do not establish compatibility or improved performance.

For `this CLI has no complete local package`, verify the package layout and use the complete ZIP's `bin\codex.exe`. Do not use an executable path in place of the `app-server` subcommand. On an error or unknown outcome, inspect status before retrying. Keep new context-index records intact: older-reader compatibility and downgrade recovery are unverified, so reverting an EXE alone is not a validated rollback.

### Known limitations

The index does not automatically infer task completion, instruction expiry, or semantic relevance. Focus must be selected explicitly; without it, the conservative active-task view can retain unrelated details. User/control/unknown and unclassified roots can accumulate independently of summaries, limiting achievable context reduction. Existing summary compaction is still needed when the active set is too large. Projection selects cached active resident positions, but index policy changes clone metadata and rebuild derived sets; index, audit, retained history and original-store growth remain possible. No total process-memory bound or measured performance improvement is claimed. Required archived originals may need explicit `read`; automatic rehydration is not claimed.

Cache coverage is the latest completed sampling response; compaction/prewarm are not observed. Observation time is a host completion time, not server cache creation. Missing metrics remain unknown; malformed metrics are invalid. Unprovided TTL/expiry cannot establish a cache deadline or per-original cache hit, and cache expiry cannot remove required context.

Original lookup is restricted to the current conversation's authorized store. Ephemeral originals may be truncated or unavailable, and already missing originals cannot be reconstructed. Missing IDs, errors, or disabled retrieval are not successful lookup or proof of absence. Forced reset, automatic authentication, raw fallback, and automatic resending of requests with unknown outcomes are excluded.

Pre-relocation source local resume/fork, concurrent compaction and persistence-failure tests passed within the 20 selected suites; final executable verification is pending. Downgrade recovery, actual-model summary quality, Desktop integration, physical keyboard/IME/voice, first-time installation, and sustained workloads remain unverified. No claim is made that all GUI delays, memory growth, or crashes are resolved. Broader memory/CodeMode/Core-store/runtime/history/QSC/cache/refactoring/multi-vendor work is deferred to R42.

### 개요

이 파일은 릴리스 빌드 전에 동결하는 소스 검증 기록입니다. 아래 최종 산출물의 대기·미검증 표시는 소스 동결 시점의 상태입니다. 공개 릴리스 본문은 이 영한 기록 전체를 보존하고 실제 빌드 소스·설정·실행본 및 패키지 검사·Desktop 식별 정보·감사 결과·SHA-256 표를 담은 영한 릴리스 검증 부록을 추가합니다. 이 부록은 발행 전에 실제 근거로 완성해야 하며 소스 시험으로 대신하지 않습니다.

Arcvera-Core는 독립적인 Semantic Versioning을 사용하며 Codex 0.167.0은 소스 출처로 표시합니다. Arcvera-Core 자체의 공개 CLI 명령·옵션, app-server 프로토콜, 네이티브 도구 API를 버전 관리 대상으로 삼습니다. 공식 Codex CLI와의 호환성이나 상호 교체는 지원 범위에서 제외하며, OpenAI 서버 통신과 이에 필요한 서버 API·인증 경로는 지원합니다. 1.0.0부터 공개 인터페이스의 비호환 변경은 major를, 호환되는 기능 추가는 minor를, 호환되는 수정은 patch를 올립니다. 초기화 계약에서는 사전 릴리스·빌드 메타데이터를 포함한 Core 전체 릴리스 버전이 정확히 일치해야 하므로 클라이언트는 대상 릴리스마다 확인해야 합니다. R41·R42는 작업 범위 추적명이며 릴리스 버전이 아닙니다. 이번 기능 릴리스의 예정 버전은 `1.0.0`, 태그는 `v1.0.0`입니다.

### 변경 사항

- 초기화할 때 `capabilities.extensions["arcvera/core"].version`이 서버의 Core 전체 버전과 같아야 합니다. 선언 누락·잘못된 형식·버전 불일치는 세션 초기화 전에 JSON-RPC 오류 `-32600`으로 거절합니다. 함께 제공하는 자사 클라이언트는 빌드된 Core 버전을 선언하며, Desktop의 `clientInfo.version`에는 자체 UI 버전을 유지합니다.
- 미사용 워크스페이스 패키지 `codex-agent-extension`, `codex-guardian-v3`, `codex-cloud-client`, `codex-core-api`, `codex-thread-manager-sample`, `codex-v8-poc`, `codex-utils-readiness` 7개를 제거했습니다. 필요한 Windows·sandbox·음성·설정 도우미는 유지합니다. 선언된 의존성 관계·잠금 파일 검사는 실행본 시험을 대신하지 않습니다.
- OpenDIY가 추가한 배치 로그·캐시 응답/wire 진단 기록·Drive 내보내기와 해당 세션 제어를 제거했습니다. 공식 Codex 로그·텔레메트리·대화 저장은 유지합니다. 이전 로그 설정은 읽지 않으며, 기존 설정·로그 파일은 자동 삭제하거나 이전하지 않습니다. 이전 릴리스 노트는 당시 동작을 설명합니다.

- 호스트가 관리하는 밴더 독립적인 인덱스에 원문 없이 출처 ID·작업 상태·의존관계·활성 제외 및 재활성화 이벤트를 기록합니다.
- Core 체크포인트 복원과 로컬 저장소 이관에서 원문 해시와 호스트가 준비한 본문의 해시를 구분합니다. 잘린 본문으로 새 원문의 동일성을 판단하지 않으며, ID 없는 반복 항목은 출현 횟수로 대조하고 누락된 메모리 내 출처는 보수적으로 유지합니다. 실제 rollback은 압축 체크포인트의 정책을 복원하는 대신 폐기한 작업 정책을 초기화합니다.
- 에이전트 간 메시지 기록은 전달 완료를 확인한 뒤 영속화 permit을 취득합니다. response-item append가 불확실하면 permit을 해제하기 전에 복구 오류를 표시해 후속 정책 변경이 저장되지 않은 출처를 수용하지 못하도록 합니다.
- `set_focus`로 현재 작업을 선택합니다. 해당 작업의 참조 폐포에는 참조 중인 완료 작업을 유지하며, 무관한 작업의 분류된 상세 내용은 활성 상태여도 제외합니다. focus가 없으면 활성 작업을 보수적으로 유지합니다. 사용자·제어·알 수 없는 종류·미분류·기존의 불투명한 출처와 불완전한 도구 그룹을 보호하며, 새로 생성한 호스트 출처 확인 요약은 캡처한 focus를 따릅니다.
- 네이티브 `context_index` 도구는 관련 메타데이터 `list`(명시적 `include_unrelated`로 보관 항목 탐색), 크기가 제한된 원문 `read`, 리비전을 검사하는 원자적 `apply`, 크기가 제한된 `audit` 요약 또는 정확한 이벤트 JSON 조각을 제공합니다. 메타데이터와 과거 내용은 권한을 부여하지 않습니다. 외부 메모리 조회가 비활성화된 경우 그 상태를 유지합니다.
- Sampling·prewarm·로컬 및 원격 압축에 문맥 구성 경로를 연결합니다. 정책 리비전이 바뀌면 WebSocket 연결 문맥을 무효화하며, 이전 정책으로 시작한 전경·백그라운드 압축 결과가 새 정책을 덮어쓰지 않아야 합니다. 현재 사용자·제어·미분류 출처는 요약과 별도로 유지합니다. 영속 변경 결과가 불확실하면 cold resume 전까지 후속 sampling·변경·압축을 차단합니다. 시험 모듈 이동 전 소스의 로컬 회귀시험에서 선택한 시험 범위의 해당 실패 경계를 검사했으며, 최종 실행본 검증은 대기 중입니다. [설계·이전·복구 안내](../context-index.ko.md)에 경계와 검증 의무를 명시합니다.
- 성공한 네이티브 apply의 완료된 호출·결과 그룹만 모델 재전송에서 제외하며 원시 이력·감사는 보존합니다. 요청 탐색 메타데이터에는 도달 가능한 작업 이름과 크기가 제한된 식별자를 넣으며 캐시 관측 시각은 자동 삽입하지 않습니다.
- 최근 완료한 sampling usage에서 응답 단위 캐시 `hit`·`miss`·`unknown`·`invalid`, 호스트 관측 시각, 요청 시 캡처한 인덱스 리비전을 제공합니다. 합계 수치로 출처별 적중을 판단하지 않습니다. upstream이 보관·만료 메타데이터를 제공하지 않아 TTL·만료 시각은 `unknown`이며 adapter가 확인한 만료 지원을 주장하지 않습니다. 캐시 상태로 원문·필수 문맥을 삭제하지 않습니다.
- 원격 압축 trace 요청 메타데이터는 trace 활성 여부를 확인하기 전에 입력을 JSON 값으로 복제하는 대신 입력 필드를 빌려 사용합니다. 실행 중 지연·메모리 효과는 아직 측정하지 않았습니다.
- 기존 R41의 광범위한 아키텍처 작업은 [R42 로드맵](../roadmap/R42.md)으로 이관합니다.

### 시작하기

이전 클라이언트와 공식 Codex CLI는 새 선언 없이 이 서버를 초기화할 수 없습니다. 같은 전체 릴리스의 CLI·서버·helper와 Core 1.0.0 연동이 검증된 Desktop 릴리스를 사용합니다. 직접 구현한 클라이언트는 검증한 패키지 또는 daemon 상태에서 대상 서버 버전을 확인하고 `initialize`에 `"capabilities":{"extensions":{"arcvera/core":{"version":"1.0.0"}}}`를 전송해야 합니다. 여기에 Desktop UI 버전을 넣지 않습니다. 선언이 거절된 뒤 같은 연결에서 선언을 바로잡아 초기화를 다시 요청할 수 있습니다. 버전을 추측하거나 인증을 바꿔 오류를 우회하지 않습니다. 기존 설정·인증·대화 파일은 유지하며, 이 연결 변경 때문에 삭제할 필요는 없습니다. 승인된 서버·데이터 업데이트 전에는 이전 전체 패키지와 적절한 백업을 보관합니다. 구버전 실행 파일만 복원하는 것은 1.0.0이 기록한 데이터의 지원되는 하향 복구가 아닙니다.

다음 안내는 검증한 R41 전체 패키지를 공개한 뒤 적용합니다. 현재 후보에는 검증된 다운로드용 R41 자산이 없습니다.

1. 발행될 릴리스에서 `arcvera-core-1.0.0-windows-x86_64.zip`과 `SHA256SUMS.txt`를 받습니다.
2. ZIP의 SHA-256을 최종 체크섬 파일·표와 대조하고 새 폴더에 폴더 구조를 유지해 압축을 풉니다.
3. `bin\codex.exe`를 실행합니다. CMD 사용은 필수가 아닙니다. `codex-package.json`, `package-receipt.json`, `bin` 폴더를 함께 유지하고 이전 전체 패키지는 복구용으로 보관합니다.

| 실행 경로 | 용도 |
| --- | --- |
| `bin\codex.exe` 또는 `codex-patched.cmd` | 기본 실행. 설치 상태·설정에 따라 호환되는 로컬 공유 서버 재사용 가능 |
| `codex-local.cmd` | `--no-daemon`으로 별도의 내장 백엔드 실행 |
| `bin\codex.exe --remote <address>` | 필요한 인증을 설정한 명시적 원격 연결 |

포함된 기본 launcher는 인자를 전달하며 기존 서버 교체, 원격 주소 설정, 모바일 페어링은 수행하지 않습니다. 자동 선택한 서버가 호환되지 않거나 버전을 확인할 수 없으면 내장 백엔드로 실행될 수 있습니다. 실제 서버의 식별 정보를 확인해야 합니다.

개별 `codex.exe`, `codex-app-server.exe`, `codex-code-mode-host.exe`는 같은 릴리스의 것을 사용합니다. 실제 실행하는 EXE와 같은 폴더에 helper를 `codex-code-mode-host.exe`라는 정확한 이름으로 둡니다. helper가 없으면 `os error 2`가 발생할 수 있습니다. 이 세 파일은 전체 설치 패키지가 아닙니다. 음성 리소스·launcher·updater 지원·관리형 서버 업데이트에는 전체 ZIP이 필요합니다.

### 공유 서버 업데이트

다음 절차는 향후 검증한 패키지를 위한 안내이며 현재 후보에서는 실행하지 않았습니다. 발행만으로 R41을 설치하거나 운영 서버를 전환하지 않습니다. 승인된 전환 전에는 진행 중 작업을 마치고 대화의 shell 도구 밖에서 별도 PowerShell 창을 사용합니다. 업데이트는 클라이언트 연결을 끊고 실행·대기 중인 작업을 중단할 수 있습니다. CLI 경로나 Desktop 설정만 바꿔도 실행 중인 서버가 교체되지는 않습니다.

[이전·복구 제한](../context-index.ko.md#영속화이전복구)을 확인한 뒤 압축을 푼 전체 패키지 루트에서 실행합니다.

```powershell
& ".\bin\codex.exe" app-server daemon update --from-cli
if ($LASTEXITCODE -ne 0) { throw "Shared server update failed; review the error above." }
& ".\bin\codex.exe" app-server daemon start --existing-installation
if ($LASTEXITCODE -ne 0) { throw "Shared server startup failed; review the error above." }
& ".\bin\codex.exe" app-server daemon status --json
```

`--from-cli`는 전체 패키지를 복사해 관리형 서버 버전으로 고정합니다. 종료를 요청하며 유예 기간 뒤 강제 종료할 수 있습니다. 인증·대화 저장소를 삭제하지 않습니다. 작업 중단을 감수할 준비가 됐을 때만 패키지 복사 확인에 응답합니다.

재접속 전에 `status`가 `running`인지, `managedCodexVersion`·`appServerVersion`·`cliVersion`이 최종 공개 버전과 같은지 확인합니다. 예정 값은 `1.0.0`이며 최종 실행본 확인 전입니다. 버전 일치만으로 호환성이나 성능 개선이 검증되지는 않습니다.

`this CLI has no complete local package` 오류가 나면 폴더 구조를 확인하고 전체 ZIP의 `bin\codex.exe`를 사용합니다. `app-server` 하위 명령 대신 실행 파일 경로를 넣지 않습니다. 오류나 결과 불명 시 재시도 전에 상태를 확인합니다. 새 context-index 기록을 보존해야 합니다. 구버전 reader 호환성·하위 버전 복구는 미검증이므로 EXE만 되돌리는 것은 검증된 복구가 아닙니다.

### 검증

| 대상 | 현재 근거 범위 |
| --- | --- |
| Core 버전 계약 | 새 격리 RED/GREEN 3쌍: protocol과 daemon은 모듈 이동 소스, AppServer는 기존 모듈을 변경 없이 포함한 추가 r41_initialize 대상에서 실행. 원래 all 대상의 GREEN은 미실행. daemon 모듈 4건 통과. 정확한 소스 대조로 과거 실행의 식별 정보 보존. 최종 실행본·Desktop 결과는 릴리스 검증 부록에 기록 |
| 소스 동작 | 시험 모듈 이동 전 1.0.0 소스: 로컬 네이티브 시험 20개 묶음, 중복 제외 89개 통과. 선택한 범위의 미실행 시험 없음 |

| 최종 Windows 실행본·패키지 | 빌드 식별·버전 실행·패키지 구조·체크섬 미검증 |

| 설치·운영 전환 | 발행으로 수행하지 않는 별도 작업 |

격리한 1.0.0 소스에서 버전 계약 시험 3건이 각각 관련 제품 코드의 변이 상태에서 실패하고 복원 후 통과했습니다. 사전 릴리스·빌드 메타데이터를 포함한 Core 전체 버전의 정확한 선언, 세션 진입 전 비호환 클라이언트 거절과 올바른 선언으로 재시도, 연결이 열린 상태에서 해당 요청의 서버 거절을 신속히 보고하는 동작을 검사했습니다. Core 선언이 일치하면 Desktop UI 버전은 달라도 허용합니다. App Server 변이는 예상하지 않은 성공 응답에서 즉시 실패했으며 예상했던 타임아웃은 관측되지 않았습니다. 같은 시험 3건이 시험 모듈 이동 전 소스에서도 통과했습니다. 이 성공 재실행은 과거 변이 시험 근거와 구분하며, 최종 릴리스 실행본·Desktop 연동·실제 OpenAI 인증 요청을 검증한 결과가 아닙니다.

시험 모듈 이동 전 소스의 Windows 로컬 컨텍스트 회귀시험 20개 묶음에서 중복을 제외한 89개 시험이 통과했으며, 선택한 범위에 미실행으로 남은 시험은 없습니다. 최종 실행본 검증과 릴리스 전체 수용은 대기 중입니다. focus·의존관계, HTTP/WS 요청 문맥, 정책 변경 후 연결 문맥, 캐시 귀속, 오래된 압축 결과, 영속화 실패, 취소된 대기자, 이관, cold resume, 실제 fork·원문 조회를 검사했습니다. 네트워크 시험은 합성 상대 서버를 사용했으며 실제 OpenAI 인증 요청은 실행하지 않았습니다.

시험 모듈 이동 전 소스에서 로컬 문맥 구성·정규화·직렬화만 측정한 기록입니다. 출처 100/1,000/10,000개마다 준비 측정 5쌍과 본 측정 30쌍, 총 180개 표본을 사용했습니다. 요청 크기는 138,992/1,388,192/13,898,192바이트에서 15,245/140,187/1,391,389바이트로 89.0%/89.9%/90.0% 줄었습니다. 중앙값은 3.380/35.120/557.740 ms에서 0.470/3.643/54.587 ms로, p95는 5.148/39.917/647.491 ms에서 0.911/4.894/66.233 ms로 줄었습니다. 중앙값은 가운데 두 값의 평균이며 p95는 최근접 순위로 계산했습니다. 모델·네트워크 지연, 프로세스 전체 메모리, 앱 장시간 부하는 포함하지 않습니다.

위 회귀시험과 측정은 `#[cfg(test)]` 모듈 두 개를 별도 파일로 옮기기 전에 실행했습니다. 전체 빌드 입력을 대조해 두 모듈의 배치와 필수 파일 고지만 변경됐고, 원래 시험 본문과 제품 코드의 바이트가 정확히 복원됨을 확인했습니다. 새 배치의 버전 계약 세 사례는 각각 RED/GREEN으로 결함 탐지 능력을 확인했고 daemon 모듈 네 시험도 통과했습니다. AppServer 시험 쌍은 기존 initialize 모듈을 변경 없이 포함한 r41_initialize 대상을 사용했으며, 원래 all 대상의 GREEN은 실행하지 않았습니다. Protocol과 daemon 결과는 실제 실행 당시의 소스 식별 정보를 유지하며, 추가된 대상과의 관계는 전체 입력의 정확한 비교로 확인했습니다. 최종 실행본·Desktop·발행의 별도 검증 근거는 릴리스 검증 부록에 기록합니다. 과거 시험을 새 파일 배치에서 실행한 결과로 표시하지 않습니다.

R39·R40의 시험 수치·실행본·체크섬·감사 결과는 과거 근거이며 R41 수용을 증명하지 않습니다. 소스 확인, 계측 추가, 빌드 성공, 감사만으로 원래 실행 중 문제가 해결됐다고 판단하지 않습니다.

### 알려진 제한
