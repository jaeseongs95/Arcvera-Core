# Arcvera-Core 1.0.1 — Independent home and manual updates / 전용 홈과 수동 업데이트

## English

### Overview

Native Windows x86-64 hotfix 1.0.1, based on the same Codex 0.167.0 source lineage as 1.0.0. This source document records pre-build evidence as of 2026-11-13. Final artifacts and publication are not established by this snapshot; the release body must append the final bilingual verification record.

### Changes

* The public CLI is `arcvera`; the Windows package includes `bin/arcvera.exe`, `arcvera.cmd` and `arcvera-local.cmd`.
* The default home is `~/.arcvera`. `ARCVERA_HOME` selects an existing directory; `CODEX_HOME` is ignored. Configuration, authentication, SQLite and daemon paths follow the Arcvera home. No existing profile is imported automatically.
* Inherited automatic update feeds, installers and background update loops are disabled, including persisted enable settings. Download future releases manually. Explicit local managed-server replacement using `--from-cli` remains available.
* Dotenv files cannot override either Arcvera or upstream product-control environment variables.
* `arcvera app` and TUI `/app` cannot launch or install the upstream Desktop app. They report the Arcvera release URL instead; startup tips no longer recommend the upstream installer. `doctor` does not query the upstream Desktop update feed.

### Getting started

Download the complete `arcvera-core-1.0.1-windows-x86_64.zip` and `SHA256SUMS.txt`, compare the ZIP hash, and extract it into a new folder. In the download directory:

```powershell
Get-FileHash .\arcvera-core-1.0.1-windows-x86_64.zip -Algorithm SHA256
```

Then, in the extracted directory:

```powershell
.\bin\arcvera.exe
```

`arcvera.cmd` passes arguments to the same CLI. `arcvera-local.cmd` adds `--no-daemon` for an embedded backend. Sign in separately in the new Arcvera home. Official Codex and ChatGPT installations are not required. Keep package metadata and all helper resources together. Internal helpers retain the names `codex-app-server.exe` and `codex-code-mode-host.exe`; use the same release for all three binaries. Individual executable downloads are not complete managed-server packages. Voice requires the separately installed Microsoft Visual C++ v14 X64 runtime; see [runtime instructions](../../tools/windows-cli/RUNTIME.md).

### Shared server update

Finish active work and disconnect clients before replacing an Arcvera managed server: replacement can restart it and interrupt connected work. These commands use only Arcvera's selected home and the complete local package:

```powershell
.\bin\arcvera.exe app-server daemon update --from-cli --yes
.\bin\arcvera.exe app-server daemon start
.\bin\arcvera.exe app-server daemon status --json
```

Check that the actual server reports `1.0.1` and its managed executable is under the selected Arcvera home. Extracting a ZIP or choosing a CLI in Desktop does not replace an already running server. A custom home must already exist before setting `ARCVERA_HOME`. For recovery, retain the previous complete package and explicitly select it after finishing connected work. Do not delete existing databases or authentication files to recover. Data transfer from another product is a separate, user-requested operation. Clients must declare the server's exact full Core version; 1.0.0 clients are not accepted by 1.0.1.

### Validation

Pre-build evidence: an isolated actual 1.0.0 package successfully started, reported its version/path, and stopped under a fresh private home. The originally reported failure was not reproduced there. The current native test executables passed 80 daemon, 5 home-resolver and 11 argument/environment tests when launched directly in an isolated Windows Job. One daemon fixture is intentionally ignored as a standalone test and is exercised by its parent test. A Cargo-mediated managed-child launch failed with Windows access denied; the retained direct-execution result does not erase that runner limitation. Package/launcher and external-runtime tests passed 35 cases after updating the product-name fixture. Targeted Windows TUI tests passed for the daemon menu, disabled update actions, external editor, server-version guidance and local-daemon behavior after reviewing the affected snapshots. Unix-only reconnect coverage was not executed on Windows. Final 1.0.1 package startup remains pending at this source snapshot. The final verification appendix must identify the actual source and binary hashes and results.

### Known limitations

The direct cause of the original nested SQLite/control-socket connection error remains unproven. This release corrects independently confirmed home-sharing and updater defects; it does not claim that every startup error has the same cause. Real-account/model requests, physical IME, audio, sustained workloads, clean-PC runtime installation and final Desktop integration have not been established by this pre-build snapshot. Full upstream-name removal, Java migration, a new automatic updater, multi-vendor login and profile-migration tooling are excluded. Original protocol identifiers, internal helper names and required legal attribution remain. Existing data is preserved without automatic migration.

### Source and integrity

The complete package includes corresponding project source, AGPL-3.0-or-later, the original Apache license and preserved notices. See [modifications](../../MODIFICATIONS.md), [source import](../source-import.md) and [packaging](../../tools/windows-cli/README.md). Product builds run locally, not in GitHub Actions. No Microsoft CRT DLL or installer is bundled. Final commit identifiers, compiler/profile settings, executable and ZIP hashes, remote asset verification and independent audit belong in the post-build verification appendix. No final checksum is available at this snapshot.

## 한국어

### 개요

1.0.0과 같은 Codex 0.167.0 소스 계보를 기반으로 하는 Windows x86-64 네이티브 핫픽스 1.0.1입니다. 이 소스 문서는 2026-11-13 빌드 전 근거를 기록합니다. 이 기준 시점만으로 최종 실행물·발행을 입증하지 않으며, 릴리스 본문에 영한 최종 검증 기록을 추가해야 합니다.

### 변경 사항

* 공개 CLI는 `arcvera`이며 Windows 패키지에 `bin/arcvera.exe`, `arcvera.cmd`, `arcvera-local.cmd`를 포함합니다.
* 기본 홈은 `~/.arcvera`입니다. `ARCVERA_HOME`은 기존 디렉터리를 선택하며 `CODEX_HOME`은 사용하지 않습니다. 설정·인증·SQLite·daemon 경로는 Arcvera 홈을 따릅니다. 기존 프로필을 자동으로 가져오지 않습니다.
* 저장된 활성 설정을 포함하여 상속된 자동 업데이트 피드·설치기·백그라운드 updater를 비활성화합니다. 이후 버전은 직접 다운로드하십시오. `--from-cli`를 통한 명시적 로컬 관리 서버 교체는 유지합니다.
* Dotenv 파일은 Arcvera와 원본 제품의 제어 환경변수를 덮어쓸 수 없습니다.
* `arcvera app`과 TUI `/app`은 원본 Desktop 앱을 실행하거나 설치하지 않고 Arcvera 릴리스 주소를 안내합니다. 시작 도움말에서도 원본 설치기를 권하지 않으며 `doctor`는 원본 Desktop 업데이트 피드를 조회하지 않습니다.

### 시작하기

전체 `arcvera-core-1.0.1-windows-x86_64.zip`과 `SHA256SUMS.txt`를 받고 ZIP 해시를 비교한 뒤 새 폴더에 압축을 풉니다. 다운로드 폴더에서 확인합니다.

```powershell
Get-FileHash .\arcvera-core-1.0.1-windows-x86_64.zip -Algorithm SHA256
```

압축을 푼 폴더에서 실행합니다.

```powershell
.\bin\arcvera.exe
```

`arcvera.cmd`는 같은 CLI에 인자를 전달합니다. `arcvera-local.cmd`는 `--no-daemon`으로 내장 백엔드를 실행합니다. 새 Arcvera 홈에서 별도로 로그인하십시오. 공식 Codex·ChatGPT 설치는 필요하지 않습니다. 패키지 메타데이터와 helper 리소스를 함께 유지하십시오. 내부 helper 이름은 `codex-app-server.exe`, `codex-code-mode-host.exe`이며 실행 파일 세 개 모두 같은 릴리스를 사용합니다. 개별 실행 파일만으로는 완전한 관리 서버 패키지가 되지 않습니다. 음성에는 Microsoft Visual C++ v14 X64 런타임을 별도로 설치해야 합니다. [런타임 안내](../../tools/windows-cli/RUNTIME.md)를 따르십시오.

### 공유 서버 업데이트

Arcvera 관리 서버를 교체하기 전에 진행 중 작업을 마치고 클라이언트 연결을 종료하십시오. 교체 시 서버가 재시작되어 연결된 작업이 중단될 수 있습니다. 다음 명령은 선택한 Arcvera 홈과 완전한 로컬 패키지만 사용합니다.

```powershell
.\bin\arcvera.exe app-server daemon update --from-cli --yes
.\bin\arcvera.exe app-server daemon start
.\bin\arcvera.exe app-server daemon status --json
```

실제 서버 버전이 `1.0.1`이고 관리 실행 파일이 선택한 Arcvera 홈 아래에 있는지 확인하십시오. ZIP을 풀거나 Desktop에서 CLI를 선택하는 것만으로 실행 중 서버가 교체되지는 않습니다. 사용자 지정 홈은 `ARCVERA_HOME` 설정 전에 존재해야 합니다. 복구를 위해 이전 전체 패키지를 보관하고 연결된 작업을 마친 뒤 명시적으로 선택하십시오. 복구 목적으로 기존 DB나 인증 파일을 삭제하지 마십시오. 다른 제품의 데이터 이전은 별도의 사용자 요청으로 수행합니다. 클라이언트는 서버와 정확히 같은 전체 Core 버전을 선언해야 하며 1.0.0 클라이언트는 1.0.1에 연결할 수 없습니다.

### 검증

빌드 전 근거: 격리한 실제 1.0.0 패키지는 새 비공개 시험 홈에서 시작·버전/경로 보고·종료에 성공했습니다. 최초 보고 오류는 그 환경에서 재현되지 않았습니다. 현재 네이티브 시험 실행 파일을 격리된 Windows Job에서 직접 실행하여 daemon 80건, 홈 resolver 5건, 인자·환경변수 11건이 통과했습니다. daemon fixture 1건은 단독 시험에서 의도적으로 제외하며 상위 시험이 실행합니다. Cargo를 거친 관리 자식 실행은 Windows 접근 거부로 실패했으며, 보존한 직접 실행 결과가 이 실행기 제약을 없애지는 않습니다. 제품명 fixture 수정 후 패키지·launcher·외부 런타임 시험 35건이 통과했습니다. 관련 스냅샷을 검토한 뒤 Windows TUI의 daemon 메뉴·업데이트 차단·외부 편집기·서버 버전 안내·로컬 daemon 표적 시험이 통과했습니다. Unix 전용 재연결 시험은 Windows에서 실행하지 않았습니다. 이 소스 기준 시점에서 최종 1.0.1 패키지 기동은 아직 대기 중입니다. 최종 검증 부록에 실제 소스·실행 파일 해시와 결과를 기록해야 합니다.

### 알려진 제한

최초의 중첩 SQLite/control-socket 연결 오류는 직접 원인이 입증되지 않았습니다. 이 릴리스는 별도로 확인한 홈 공유와 updater 결함을 수정하며 모든 기동 오류의 원인이 같다고 주장하지 않습니다. 실계정·실모델 요청, 물리 IME, 음성, 장시간 부하, 새 PC 런타임 설치, 최종 Desktop 통합은 이 빌드 전 기준 시점으로 입증되지 않았습니다. 원본 명칭의 완전한 제거, Java 전환, 새 자동 updater, 멀티벤더 로그인, 프로필 이전 도구는 제외합니다. 원본 프로토콜 식별자·내부 helper 명칭·필수 법적 출처 고지는 유지합니다. 기존 데이터는 자동 이전 없이 보존합니다.
